# CodeMgr v1.1 — 断链修复 + 高危交互治理 + 项目分组 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复 v1.0 遗留的断裂链路（端口雷达 processName 为空、托盘无法退出、PEB cmdline 偏移存疑）与高危交互（批量 kill 误伤、全选无视过滤器），兑现 CHANGELOG 已宣称但未交付的磁盘 IO 速率 UI，并实现**按项目分组**——设计文档中与 System Informer 拉开差距的核心差异化能力。

**Architecture:** 沿用 v1.0 三层架构（C++ addon → Electron main → contextBridge → React/Zustand），不引入新层。项目分组在 native 层为 `ProcessInfo` 增加 `cwd` 字段（从已读取的 PEB 缓冲中取 `RTL_USER_PROCESS_PARAMETERS.CurrentDirectory`，边际成本极低），渲染层新增纯函数 `groupByProject` 聚类，ProcessPanel 增加分组视图模式。

**Tech Stack:** Electron 43.2.0 / React 18 + TypeScript / Tailwind CSS 3 / Zustand 4 / cmake-js / Vitest

**Spec reference:** `docs/superpowers/specs/2026-07-29-codemgr-design.md` §3.2 进程面板（按项目分组）、§8 版本规划 v1.1
**问题清单来源:** v1.0 代码审查（2026-07-29），关键条目在各 Task 开头标注文件:行号。

**版本完成判据：**
1. 端口雷达表格正确显示占用进程名（不再是 '—'）
2. 托盘菜单"退出"能真正退出应用，热键注销、进程不残留
3. 批量结束只杀用户选中的 PID；确认文案与实际行为一致；全选只作用于过滤后子集
4. 一键"结束所有 node.exe"预设可用，且不会误杀 CodeMgr 自身（保护名单）
5. 性能面板磁盘子标签显示读/写速率与活动时间%（与 CHANGELOG 一致）
6. 进程面板可按项目分组展示，同项目进程归为一组、可整组结束
7. 亮色主题可读、主题/排序/过滤重启后保留
8. `pnpm test:native && cd app && pnpm vitest run` 全绿；涉及 native 采集层改动后 `pnpm bench` 无回归（processScan p99 ≤ 20ms）

## Task 2: 端口雷达 processName 接通

**目标：** `netScan()` 返回的每条连接带真实 `processName`，端口雷达表格显示占用进程名。

**方案选择：** 在 **native 层**填充——`netScan` 内部枚举一次 pid→name 映射（复用 `NtQuerySystemInformation` 进程枚举，只取 pid+name，不读 PEB cmdline，开销 < 2ms）。比在 TS 层 join 省一次 IPC、且 killByName 之外的调用方也受益。

**Files:**

- Modify: `codemgr-native/tests/net.test.ts`

## Task 3: PEB cmdline 偏移实测验证与修正

**目标：** 用真实数据验证 `process_collector.cpp:199` 的偏移试探是否取到 CommandLine（含参数）而非 ImagePathName（纯 exe 路径）；若取错则修正。这是**调查性 Task**——先证伪，再动手。

**问题依据：** 偏移候选按 `{0x60, 0x68, 0x70, 0x78}` 顺序试探，取第一个"看起来合法"的 UNICODE_STRING。x64 下 0x60 是 ImagePathName、0x70 才是 CommandLine（布局自 Vista 起稳定）。若 0x60 先命中，所有 cmdline 都变成无参 exe 路径，`processLabels.ts` 基于参数的规则（vite/npm run dev/jest）大面积失效。

**Files:**

- Modify（视验证结果）: `codemgr-native/src/process_collector.cpp`

- [ ] **Step 1: 写诊断脚本**

Create `codemgr-native/bench/cmdline.check.ts`：
```ts

import native from '../index';

const procs = native.processScan();
// 找一个我们知道带参数的进程：当前 node 进程自己
const self = procs.find((p) => p.pid === process.pid);
console.log('self pid:', process.pid);
console.log('self cmdline:', JSON.stringify(self?.cmdline));
console.log('expected to contain:', process.execPath, '+ script args');

// 统计：有多少 cmdline 以 .exe 结尾（疑似只有路径无参数）
```

## 依赖关系与执行顺序

```
Task 1（托盘退出）          ─┐ 独立，可最先做
Task 2（processName）       ─┤ 独立
Task 3（PEB 诊断）          ─┤ 独立，但 Task 8 依赖其结论（同一块 PEB 代码）
Task 4（批量 kill 安全）    ─┤ 独立；Task 8 的"结束本组"依赖其 killByPids
Task 5（状态修复包）        ─┤ 独立
Task 6（磁盘 IO UI）        ─┘ 独立
Task 7（主题+持久化）       ← Task 5 之后（都碰 store/hook，避免冲突）
Task 8（项目分组）          ← Task 3、Task 4、Task 7 之后
Task 9（详情侧栏）          ← Task 8 之后（用 cwd 字段）
Task 10（收尾）             ← 全部之后
```

Task 1-6 彼此独立，可并行或由不同 subagent 分头执行；Task 7-9 有先后依赖。
