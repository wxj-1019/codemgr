## 阶段一：v2.1 GPU 监控

### Task 1: native GPU 采集器（gpu_collector）

**Files:**
- Create: `codemgr-native/src/gpu_collector.cpp`、`gpu_collector.h`
- Modify: `codemgr-native/src/addon.cpp`、`perf_collector.cpp`（聚合出口）、`codemgr-native/index.ts`、`codemgr-native/CMakeLists.txt`（新源文件）
- Create: `codemgr-native/tests/gpu.test.ts`

- [ ] **Step 1: 纯函数实现（internal static，不暴露测试导出）**——`ParseGpuEnginePid(const std::wstring& instanceName) -> DWORD`（宽松解析：找 `pid_` 前缀取数字，失败返 0）；`AggregateGpuSamples(instances) -> {totalPercent, map<pid, {gpuPercent, vramBytes}>}`。**不通过 Node-API 暴露**（照 spec §1.5 方案 A：与现有 cpu/disk 聚合同等待遇，纯函数单元正确性靠 code review + 集成断言覆盖，不为 GPU 破例加测试导出污染生产面）。典型实例名 `pid_1234_luid_0x00000000_0x00004501_phys_0_eng_2_engtype_3D` 解析出 1234；无 `pid_` 前缀返 0；多实例同 pid 累加。
- [ ] **Step 2: PDH 采集实现**——照 disk PDH 模式（`perf_collector.cpp:98-139` 的静态 state + 一次 init），但**关键差异：用 `PdhAddEnglishCounterW` 而非 `PdhAddCounterW`**（GPU 计数器名免本地化，见 spec §1.2"与现有 disk PDH 的关键差异"）。静态 `GpuPdhState`（query + counters + 周期计数器），`InitGpuPdh()` 用 `PdhExpandWildCardPath` 展开 `\GPU Engine(*)\Utilization Percentage` 与 `\GPU Engine(*)\Dedicated Usage`，逐个 `PdhAddEnglishCounterW`；每 5 个采样周期重展开。展开返回空 → `available=false`（不报错）。显存总量：DXGI `<dxgi1_6.h>` 的 `IDXGIFactory4::EnumAdapters1` + `IDXGIAdapter3::QueryVideoMemoryInfo(DXGI_MEMORY_SEGMENT_GROUP_LOCAL)` 取第一硬件适配器 CurrentUsage/Budget；失败 fallback per-process 求和、总量 0。**CMakeLists WIN_LIBS 加 `dxgi`**（pdh 已在；dxgi 是新依赖，见 spec §1.2）。
- [ ] **Step 3: 并入 perfCounters 返回 + 结构断言测试**——`PerfData` 加 `gpu` 字段（spec §1.3 结构）；`index.ts` 的 `NativeBindings`/`PerfData` 接口同步。gpu.test.ts 对完整 `perfCounters()` 做结构断言（available/totalPercent 范围/perProcess 形状；available=false 时其余为 0；available=true 时 perProcess 的 pid 与 processScan 的 pid 应有交集——间接覆盖聚合正确性，spec §1.5 方案 A）。
- [ ] **Step 4: 重编译 + bench**——`pnpm build` → `pnpm vitest run` → `pnpm build:electron` → `pnpm bench`（perfCounters 判据 < 10ms）。
- [ ] **Step 5: 提交** `feat(native): gpu utilization + vram collection via PDH gpu-engine counters`

## 阶段二：v2.2 进程快照对比

### Task 3: 快照存储（受控文件 IO）

**Files:**
- Modify: `app/electron/ipc-types.ts`、`app/electron/main.ts`、`app/electron/preload.ts`、`app/src/lib/ipc.ts`
- Create: `app/src/lib/snapshotTypes.ts`（SnapshotEntry/ProcessSnapshot，渲染/main 共享声明）

- [ ] **Step 1: 类型 + 通道常量**——spec §2.2 结构；IPC 加 `SNAPSHOT_LIST/SAVE/DELETE/LOAD`。
- [ ] **Step 2: main handler**——`userData/snapshots/<id>.json` 读写（照 v1.4 标签规则文件 IO 模式：main 封装 fs + 路径白名单，渲染层拿不到路径）；list 只读目录返回元信息（id/name/createdAt/count）；save 校验 schema + 上限 20（超出返错）；load/delete 按 id。**路径穿越防护**：id 必须匹配 uuid 正则 `/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i`，拒绝含 `/\\..` 的 id（防 `../../` 逃逸 userData）。save 时 id 由 main 用 `crypto.randomUUID()` 生成（渲染层不指定 id），消除穿越面。
- [ ] **Step 3: preload + ipc.ts 接线**——照 §10.1 第 5/6 步。
- [ ] **Step 4: 提交** `feat(app): snapshot persistence via controlled file io (userData/snapshots)`
